**Phase 9 needs design changes before implementation.** The proposed matcher can select the wrong winner on supported kgateway versions, restricted search conflicts with D-114, and the conformance runner cannot always establish the declared rule identity it is meant to prove.

I reviewed the local program copy recorded at `4986792`. GitHub DNS resolution failed, so I could not verify the live copy. I checked kgateway main `34e314f527` and tags `v2.3.11`, `v2.4.7`, and `v2.5.1`. The source confirms the weight setting and child-owned weights, hostname specificity in 2.5, and opt-in `route_source` in the pinned 2.4 and 2.5 releases. No tests were run or reported. No files were edited.

## P1 findings

1. **P1 · architecture · `design.md:158` — Selecting a declared listener first can exclude the actual winner.** In 2.3.11, kgateway puts routes from same-port HTTP listeners into a shared virtual-host map before sorting. A route attached to a wildcard listener can therefore compete in the same exact-host virtual host as a route attached to the exact listener. Step 1 discards the wildcard listener before the strategy sees its routes. The strategy needs to own filter-chain and virtual-host selection as well as route order, with per-minor cases for same-port overlaps and a miss in the selected virtual host. [Phase 9 design](docs/phases/phase-9/design.md:158) · [kgateway v2.3.11 listener translator](https://github.com/kgateway-dev/kgateway/blob/v2.3.11/pkg/kgateway/translator/listener/gateway_listener_translator.go#L686-L745) · [View A’s programming limits](docs/phases/phase-2/computed-rules.md:130)

2. **P1 · correctness · `design.md:162` — Replacement status cannot reliably identify the winning rule.** In 2.4.7, `Replaced Rule (N)` carries `MatchIndex`. Two rules can each have match zero, and status retains one condition of a given type per parent report. The translator also distinguishes a reported condition from the direct-response action, which depends on validation mode and can result from a delegation error without that condition. A current condition can therefore implicate the wrong winner, and its absence can miss a direct response. Preserve the parent-level finding and return unknown for rule attribution unless the evidence uniquely identifies the winning occurrence. Explicitly cover the clean delegation-only parent, which emits no route, and the unresolved parent, which can emit a 500. [Phase 9 design](docs/phases/phase-9/design.md:162) · [kgateway v2.4.7 replacement logic](https://github.com/kgateway-dev/kgateway/blob/v2.4.7/pkg/kgateway/translator/irtranslator/route.go#L310-L371) · [Status aggregation contract](docs/phases/phase-2/computed-rules.md:363)

3. **P1 · correctness · `design.md:173` — The unknown-version fallback can give a confident wrong answer for ordinary HTTPRoutes.** Consider two routes that intersect to the same virtual host, with a more specific original hostname on one and a longer matching prefix on the other. The pinned 2.5 comparator prioritizes hostname specificity, while the pinned 2.4 comparator proceeds to the path. Neither route needs delegation, weights or regex to trigger this difference. D-142’s allowlist therefore fails D-139’s unknown-input rule. Require evidence that the applicable matching and precedence semantics agree, or return “Can’t predict.” [Phase 9 design](docs/phases/phase-9/design.md:173) · [D-142](docs/decisions.md:1907) · [2.4.7 comparator](https://github.com/kgateway-dev/kgateway/blob/v2.4.7/pkg/kgateway/translator/routeutils/sortable_route.go#L19-L37) · [2.5.1 comparator](https://github.com/kgateway-dev/kgateway/blob/v2.5.1/pkg/kgateway/translator/routeutils/sortable_route.go#L24-L45)

4. **P1 · architecture · `design.md:189` — Restricted search exposes the delegation analysis withheld by D-114.** The index uses view C and returns effective matches and backends. A readable child can inherit a path, header or query condition from a hidden parent. Editing that parent can then change whether the child appears in search, its effective match, or its count. Filtering rows by the child’s read permission leaves that dependency intact. Give restricted viewers a declared-match search, or require a separately approved visibility model for effective matches. Test hidden parents, Gateways and ListenerSets with the readable route unchanged. [Search design](docs/phases/phase-9/design.md:185) · [D-114](docs/decisions.md:1660) · [D-085](docs/decisions.md:1394)

## P2 findings

5. **P2 · architecture · `design.md:139` — View D has no runtime disagreement contract.** The existing status checks help verify attachment and delegation signals. A manually sent response has no authoritative route identity, and §7.5 explicitly leaves the prediction unchanged on a mismatch. That combination cannot satisfy P-008 rule 3 where controller route output is available. Specify which evidence is checked, when a disagreement becomes a finding or `unknown`, and what happens when evidence is absent. If that check stays in Phase 12, record an explicit program exception before shipping the mirror. D-140 currently claims compliance and the plan only schedules registration. [Mirror design](docs/phases/phase-9/design.md:133) · [Program mirror rules](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L138) · [D-140](docs/decisions.md:1891)

6. **P2 · correctness · `design.md:282` — The runner conflates emitted indexes with declared indexes.** kgateway compacts delegated rules and matches before numbering them. An unnamed child’s declared rule 1 can be emitted as `_rule-0` after rule 0 fails the parent fit. Generated names on 2.3 have the same indexing problem. The metadata also omits the delegation chain. Define how the oracle proves **declared** rule identity using independent fixture evidence, such as distinct backend markers for forwarding rules, and how it reports ambiguous or unprovable cases. Use xdsview for runtime-name and metadata correlation under P-001. To close D-128 as written, also compare view C’s effective matcher with the cited translator output, or explicitly amend D-128. Winner checks alone can pass with an incorrect matcher on unexercised inputs. [Runner design](docs/phases/phase-9/design.md:279) · [Delegation compaction](https://github.com/kgateway-dev/kgateway/blob/v2.5.1/pkg/kgateway/translator/httproute/delegation_helpers.go#L57-L75) · [Metadata fields](https://github.com/kgateway-dev/kgateway/blob/34e314f527/pkg/kgateway/translator/irtranslator/policy.go#L129-L158) · [Program ownership](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L254) · [D-128](docs/decisions.md:1784)

7. **P2 · architecture · `design.md:74` — `Views.Generation` does not cover all prediction inputs.** The engine increments it on changes to views A–C. The existing inputs omit the new weight setting, the weight annotation and creation timestamps. An annotation-only edit or a setting change can flip the winner with the same views generation. Key the table on all inputs it consumes, and test that changing only the setting or annotation updates an already-cached result. [Cache contract](docs/phases/phase-9/design.md:69) · [Engine memoization](pkg/engine/views.go:22) · [HTTPRoute decoder](pkg/objects/httproute.go:125)

8. **P2 · architecture · `design.md:160` — The matching boundary omits pre-match normalization and unsupported competitors.** kgateway enables path normalization and slash merging by default, and ListenerPolicy can change those settings. Walking the table against the raw request can miss an exact route that Envoy matches. GRPCRoute also enters kgateway’s HTTP route IR, so excluding GRPCRoute from the feature does not remove it from the proxy’s candidate set. Define the supported request semantics and return unknown when listener settings or an unsupported competitor can change the result. This preserves the program boundary around policy resolution. [Matching design](docs/phases/phase-9/design.md:156) · [HCM defaults](https://github.com/kgateway-dev/kgateway/blob/34e314f527/pkg/kgateway/translator/irtranslator/fc.go#L259-L269) · [Listener policy overrides](https://github.com/kgateway-dev/kgateway/blob/34e314f527/pkg/kgateway/extensions2/plugins/listenerpolicy/listener_plugin.go#L424-L432) · [GRPCRoute translation](https://github.com/kgateway-dev/kgateway/blob/34e314f527/pkg/krtcollections/grpc_route.go#L14-L34)

9. **P2 · architecture · `design.md:212` — The authorization check does not establish the claimed equivalence to port-forward.** `create` on `pods/portforward` is the agreed send gate. The example `kubectl port-forward svc/...` also needs to discover the Service and an eligible Pod, while Snellius uses its own inventory and network path. The copy action can disclose the resolved Service’s name or existence to someone who can read only the Gateway. Keep the agreed gate, specify the additional RBAC and visibility conditions for target resolution and disclosure, and define how live traffic observations fit D-085. A hidden route change can alter a live response even when the viewer’s read permissions stay fixed. [Send and copy design](docs/phases/phase-9/design.md:205) · [Visibility design](docs/phases/phase-9/design.md:230) · [D-144](docs/decisions.md:1919)

10. **P2 · correctness · `design.md:161` — The plan leaves two roadmap deliverables without observable acceptance criteria.** Per-request losers do not establish that a route is shadowed across all requests, and the API returns up to 50 losers without specifying how to retrieve the rest. Separately, the curl examples do not establish reproduction of the request’s method, headers, query and raw path. Define which shadowing or conflicts the feature detects, how it reports an incomplete loser list, and how to verify that the generated curl sends the same request. [Roadmap](docs/roadmap.md:146) · [Prediction API](docs/phases/phase-9/design.md:175) · [Copy as curl](docs/phases/phase-9/design.md:215) · [Web acceptance plan](docs/phases/phase-9/implementation-plan.md:49)

11. **P2 · correctness · `design.md:183` — P-011 applies to unnamed rule indexes even when the viewer can read them.** Inserting a preceding rule changes an unnamed rule’s index. The index can be returned as snapshot-local evidence, but the design calls it rule identity and does not say what happens when a link or cross-tool join outlives the snapshot. Scope named rule IDs and distinguish them from snapshot-local occurrences. For D-147, record any retained rank exception per use, with its privacy justification and rekeying consequence. The proposed general handling leaves those decisions open. [Rule identity design](docs/phases/phase-9/design.md:181) · [P-011](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L223) · [D-147](docs/decisions.md:1936)

12. **P2 · correctness · `implementation-plan.md:61` — The release plan omits program acceptance gates.** A site issue is only the start of P-006: the user-facing changes must be live before release closure. E16 also needs the tagged contract and consumer notices at close. For P-012, the design mentions a green corpus on a later minor, but the plan has no bump checklist tying the predictor’s version table and fixtures to the same-change CRD, kind-list, mapping and mirror review. Make those checks explicit in the plan. [Release plan](docs/phases/phase-9/implementation-plan.md:57) · [P-006](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L103) · [P-012](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L234) · [Coordination protocol](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L295)

## P3 and P4 findings

13. **P3 · correctness · `design.md:284` — Making each loser win on another request does not verify why it lost.** A completely shadowed rule has no such request. A rule that can win elsewhere still gives no evidence for the decisive reason on the original request. Assert loser reasons on the original request, including complete shadowing and a case where more than one ordering criterion differs. Use paired requests where they discriminate matcher behavior. [Runner tests](docs/phases/phase-9/design.md:279) · [Order tests](docs/phases/phase-9/design.md:306)

14. **P4 · architecture · `design.md:141` — U2 and U10 improve attribution but leave prediction and observation with different coverage.** Both asks can land while some installs or viewers still lack a readable, current proxy snapshot. P-008 requires Snellius to work without xDS, and Phase 12 already anticipates withheld observations. Define retirement in terms of proven coverage for supported installs and viewers, or record the product decision to drop config-only prediction when that threshold is reached. [Retirement design](docs/phases/phase-9/design.md:133) · [P-008](https://github.com/DuncanDoyle/kgateway-tooling/blob/4986792/program.md#L105) · [Phase 12 visibility carry-over](docs/phase-status.md:64)
