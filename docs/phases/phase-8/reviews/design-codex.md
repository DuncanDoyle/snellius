I would revise the Phase 8 design before approving implementation. The declared-policy view can ship without a resolver. The draft still needs to close a target-existence leak and define a provenance contract that kgwctl can consume. Phase 12 also needs a visibility rule for the runtime chain itself.

## P1 findings

1. **P1 · architecture — A namespace `list` grant is insufficient for a target check in a downstream build.** Phase 8 permits `found` and `section not found` after a kind-and-namespace list check. Snellius evaluates `canList` separately from `can` and `canNamed`. A downstream authorizer can allow the list operation while denying a specific target. A readable policy would then reveal that target’s existence or section layout, including through the `has problems` filter. Authorize the named target before looking it up, retain the list requirement for absence checks, and use the same viewer-scoped result for rows, filters, facets and totals. Test a downstream authorizer that allows the bucket and denies the target. [Phase 8 design §7](../design.md:198) · [Separate visibility checks](../../../../pkg/api/visible.go:270) · [D-119](../../../../docs/decisions.md:1715)

2. **P1 · architecture — D-122 has no truthful source for required controller status.** The source vocabulary defines `controller-reported-attached` as `Attached=True`. The model and UI must also carry `Accepted`, `Attached=False`, `TargetNotFound`, and unknown reasons verbatim. Those observations have a known controller source and make no positive attachment claim. The proposed `Ancestor` type carries no source, and “worst Accepted” is a Snellius-derived summary. Amend D-122 so raw controller status has a truthful source, and label derived summaries separately. Keep positive attachment tied to the reported condition. [Source definitions](../design.md:64) · [Ancestor model](../design.md:128) · [List and detail](../design.md:161) · [D-122](../../../../docs/decisions.md:1744)

3. **P1 · architecture — Phase 12’s proposed redaction leaves the runtime chain as a side channel.** Dropping an unreadable policy’s contribution and allow-listing `typed_config` still leaves filter presence, order, counts and unmapped fields observable. A hidden policy can change those bytes while the viewer’s readable Kubernetes objects stay fixed. The draft itself lists contexts where provenance is missing, and E13 caps attribution certainty. Carry forward a requirement to withhold the entire affected runtime block unless the viewer is authorized for its full evidence scope. A withheld block must behave the same when the hidden configuration is present or absent. The transport decision can stay in Phase 12. [Phase 8 design §4.3](../design.md:103) · [Runtime visibility design](../design.md:218) · [D-085](../../../../docs/decisions.md:1394)

## P2 findings

4. **P2 · architecture — “Targeting a parent” needs a declared join and an explicit dependency set.** The draft labels the relation `declared` without specifying whether “parent” comes from `spec.parentRefs`, controller status, computed listener attachment, or an up-chain walk. Snellius exposes all of these separately. A route that names a Gateway without a section does not declare a particular listener. Reusing computed attachment to select listener policies would make the policy list depend on the D-020 mirror, and walking through an unreadable ListenerSet could reveal it through a row for a readable Gateway. Define the join from explicit refs, preserve exact section qualification, and require visibility of every intermediate object for any supported multi-hop join. An unsectioned or port-only parentRef should never produce a declared relation to a named listener. [Parent relations](../design.md:172) · [Declared and computed parents in Snellius](../../../../pkg/api/details.go:606) · [D-020 scope](../../../../docs/decisions.md:374)

5. **P2 · architecture — The E7 contract cannot express the identity and evidence its consumers need.** The sample `Relation.Subject` is `objects.Ref`, which has no section or port. `targets-parent` also has no field for the parent that justified the row. An external caller has no specified way to build `idx`, supply viewer-scoped inputs, or retain the dependency for projection. The proposed runtime relation names a level in prose, while the type has no level, field, or independent certainty slot. Give E7 a section-aware subject and a documented index or input contract. Add an external-package acceptance case for kgwctl’s existing one-shot flow. Keep runtime evidence in a separately typed xdsview-backed result, or define how the public type carries both source and certainty before promising that Phase 12 needs no model change. The program’s E7 also includes route-level xDS evidence from a separate provider, so 8.3 should record delivery of Snellius’s part of E7. [Public model](../design.md:136) · [`objects.Ref` and `ParentRef`](../../../../pkg/objects/objects.go:17) · [Runtime relation](../design.md:224) · [8.3 handoff](../implementation-plan.md:41) · [Program E7 and E13](https://github.com/DuncanDoyle/kgateway-tooling/blob/main/program.md)

6. **P2 · architecture — The pack hook arrives after the first API already needs it.** In 8.1, `Read(u)` must flag `StatusSummary`, expose precedence annotations, and supply feature data for filtering. The design assigns those interpretations to the pack, but 8.2 introduces the hook. The new `PartiallyValid` classification and fixed `Merged`/`Overridden` copy also need a pack owner. Move the necessary policy hooks into 8.1, with a neutral decoder and explicit pack input usable from both the API and kgwctl. Test that the same reason string on a core or unrelated downstream policy gets no kgateway interpretation. [Extension boundary](../design.md:208) · [8.1 API](../implementation-plan.md:19) · [8.2 hook](../implementation-plan.md:33)

7. **P2 · correctness — The list and Gateway relations lack freshness and controller attribution rules.** Selecting any `Attached=True` or the “worst Accepted across ancestors” can promote an old generation or another controller’s entry into the current install’s summary. Existing Snellius policy findings check controller identity, ownership and freshness. Preserve all conditions in the raw detail, then specify current versus historical treatment and controller scope for the summaries and reverse relations. The upstream claims also need narrower wording: “Which Gateways did it reach?” overstates the draft’s own known ListenerPolicy false positive, and the fixed “per Gateway” note ignores its stated ListenerSet and backend granularity. These inconsistencies are visible in the draft without checking kgateway source. [Controller claims](../design.md:82) · [Summaries and relations](../design.md:161) · [Existing finding guards](../../../../pkg/health/own/status.go:120)

8. **P2 · correctness — Target-check outcomes can turn incomplete collection into false missing-target reports.** A kind can be served while its watch is denied, pending, or scoped away from the target namespace. Snellius already tracks access by kind and namespace. The design also promises `section not found` without defining which section representations it can inspect. The existing kgateway checker covers a limited set of listeners and route rules, and its 2.5 implementation returns `unknown` for explicit refs. Specify `unknown` for incomplete collection and unsupported section forms. Keep the check to observable structure, with any vendor-specific section decoding behind the pack. [Target checks](../design.md:153) · [Collection access](../../../../pkg/health/ownrun.go:191) · [Existing section checks](../../../../pkg/computed/kgw24/targets.go:14) · [2.5 checker](../../../../pkg/computed/kgw25/targets.go:19)

9. **P2 · correctness — DirectResponse needs a narrower change than promotion out of `ListOnly`.** The existing status path skips `ListOnly`, and assignment puts DirectResponse in `Listed`, outside `Owned.Policies`. A blanket promotion changes more than ancestor findings. It brings the kind into policy freshness and route replacement attribution, and can affect diagnostics that iterate owned policies. Specify the intended change as status-only, with tests for a rejected DirectResponse, a status-less or uncollected DirectResponse, and unchanged route signals. Record the amendment to D-058 item 6. [DirectResponse step](../implementation-plan.md:22) · [Assignment](../../../../pkg/install/assign.go:271) · [Status gate](../../../../pkg/health/own/status.go:62) · [Route attribution input](../../../../pkg/health/ownrun.go:133) · [D-058](../../../../docs/decisions.md:1020)

10. **P2 · correctness — The new endpoints omit install scope, full policy identity in the UI, and audit integration.** The plan places the API outside `/api/v1/installs/{id}`, while the existing detail, YAML and admission paths are install-scoped. The SPA path also omits group, so policies from two registered groups with the same kind, namespace and name collide. The audit router uses an explicit table, and an unregistered core route misses the default list-summary and deliberate-read audit paths. Define the install-scoped API and SPA routes, carry group through links, and add acceptance cases for collisions, denied versus absent details, YAML link agreement and audit records. [Policy URLs](../design.md:161) · [Planned API](../implementation-plan.md:21) · [Existing routes](../../../../pkg/api/handlers.go:65) · [Audit classification](../../../../pkg/api/audit.go:70)

11. **P2 · correctness — The existing diagnostic behavior is broader than the draft’s account.** The selector branch of KGWUI-016 can stay as the M-2 exception, but 2.3 and 2.4 also use computed 016 for explicit missing refs and sections, and the verifier can produce 012. Separately, Snellius’s specialized rule-replacement handling recognizes `RouteRuleReplaced` and `RouteRuleDropped`. I found no equivalent handling for `ListenerReplaced` or `GatewayReplaced`, though generic condition display can show the raw reasons. Document what the app actually does per supported version, preserve Phase 7’s full-read gate for derived findings, and remove the open proposal to list selector matches on route pages. That proposal conflicts with D-125. [Current diagnostics](../../../../pkg/health/targets.go:90) · [Rule replacement handling](../../../../pkg/health/own/own.go:651) · [Draft controller claim](../design.md:89) · [Selector proposal](../design.md:278)

## P3 finding

12. **P3 · correctness — Test the security contract at the first shipping boundary.** Step 8.1 specifies a hidden-policy byte test, while the hidden-parent and hidden-ancestor cases appear in 8.2. The first increment already has target checks, health summaries and pagination. Its tests should vary hidden targets and ancestors while checking rows, totals, facets, links, health, and the `has problems` filter under fixed permissions. Account explicitly for Phase 7’s permitted timestamp and install-membership changes. The copy test should inspect Snellius-generated labels, since a blanket word ban conflicts with verbatim controller messages and YAML.
