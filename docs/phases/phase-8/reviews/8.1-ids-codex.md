### What the ID guarantees

The ID is an opaque, install-scoped key for **finding code + logical resource + the discriminator for that occurrence of the check**, such as an ancestor and condition type. The API sends the ID unchanged and looks up detail requests by exact ID, then checks visibility. The UI uses it for detail URLs, row keys, and equality checks when retaining fetched detail. If a finding clears or becomes unreadable, its URL returns 404. If the same finding remains visible across a permission change, it should keep its ID. The same diagnostic should keep its ID across recomputes, status reordering, and controller or Snellius restarts, provided the install and diagnostic inputs still match. Same-name recreation is a consequence of the existing logical key. An old link can resolve again when the replacement reports the same problem. `Since` has a separate lifecycle. KGWUI-002 normally uses the controller’s `lastTransitionTime`. When no timestamp is supplied, Snellius records first sight by ID in memory. An observed gap normally prunes that clock, and a Snellius restart resets it. A replacement observed without a gap can inherit that fallback clock. Message, detail, severity and timestamps stay out of the hash.
