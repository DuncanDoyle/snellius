1. **P1 correctness — Delegation responses still expose hidden routes’ matches.**  
   [details.go:1107](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/details.go:1107), [rows.go:894](/Users/ddoyle/Development/claude/snellius-phase7/pkg/explore/rows.go:894)

   Delegation dependency sets remove every HTTPRoute through `offPath`; secure-mode admission then checks those reduced sets. Nevertheless, `delegationContext` serializes every route and match along the path. Effective contexts use the same reduced dependencies.

   **Scenario:** a readable root on a readable Gateway delegates through hidden route H to readable parent P and child C. Change only H’s matcher, preserving membership and references. P’s delegation response changes `contexts[].path[].match`; C’s effective matches can change too. These are hidden configuration values, outside the approved exceptions.

   This also undermines the `state=` path after ec93910: `routeState` retains computed dropped flags whose dependency sets remove HTTPRoutes. A hidden ancestor’s matcher can therefore change inclusion under `state=dropped`.

   **Fix:** retain and authorize route dependencies for secure-mode computed facts, including contexts and flags. Preserve the older D-024 treatment only outside secure mode.

2. **P1 correctness — ListenerSet details disclose unreadable CRD metadata.**  
   [details.go:489](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/details.go:489)

   When a readable ListenerSet reports `Accepted=False/NotAllowed` and its readable parent lacks `allowedListeners`, the handler calls `gatewayCRDField` without a CRD permission check. That helper copies the watched Gateway CRD’s channel and bundle version.

   **Scenario:** a namespace reader cannot read CRDs. Change only the Gateway CRD’s bundle annotation from `v1.4.1` to `v1.5.1`. The ListenerSet detail changes `parentAllowedListeners.crdBundleVersion` and `crdField` from `missing` to `defined`. Changing its channel also changes `crdChannel`. API discovery’s approved visibility does not authorize these object annotations.

   **Fix:** omit these fields unless the CRD source is readable; add the rejected-ListenerSet case to the rule harness.

3. **P1 correctness — Shared compute bounds change readable delegation output.**  
   [details.go:934](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/details.go:934), [details.go:862](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/details.go:862)

   Projection copies truncation and `too-large` results from computations bounded across the entire install. For example, [accum.go:121](/Users/ddoyle/Development/claude/snellius-phase7/pkg/computed/kgw24/accum.go:121) retains contexts against a shared `ContextsPerInstall` counter; hidden work can exhaust it before a readable row is processed. The edge budget similarly cuts later selections.

   **Scenario:** a restricted viewer can read an entire P→C chain. An unrelated hidden route gains enough matches or delegation edges to cross a shared bound. P/C’s objects and membership remain unchanged, but their returned contexts disappear, `contextsTruncated` becomes true, or their computed reason becomes `too-large`.

   Authorizing every actual chain dependency would not resolve this unrelated-population dependency.

   **Fix:** make restricted results independent of shared-population bounds, or withhold affected computed facts based on permission-defined populations. Test both sides of each bound.

4. **P1 correctness — `/paths` exposes the hidden topology’s memory threshold.**  
   [paths.go:155](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/paths.go:155)

   `summary.unmemoised` is assigned from the shared topology’s `kept` result. [memo.go:111](/Users/ddoyle/Development/claude/snellius-phase7/pkg/paths/memo.go:111) decides that result using the size of the complete topology, before viewer filtering.

   **Scenario:** add paths exclusively in an unreadable namespace until the topology crosses 2 MiB. A restricted viewer’s visible rows remain identical, but `summary.unmemoised` appears. This also affects scoped requests.

   **Fix:** suppress this implementation-state field for restricted viewers. This is separate from the accepted projection-cost and unscoped-SAR limitations.

5. **P1 correctness — Hidden root buckets can change `/namespaces` from 200 to 503.**  
   [namespaces.go:38](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/namespaces.go:38)

   The endpoint prefetches buckets discovered from all rows, including hidden ones. Each distinct uncached bucket spends the request’s SAR budget; exceeding 1,000 produces `503 authz-unavailable`. Route lists similarly enumerate hidden root buckets, and report projection discovers buckets from hidden own-object findings.

   **Scenario:** with cold permission caches and unchanged permissions, arrange existing hidden buckets just below the check limit. Create one hidden route in another existing, unreadable namespace. `/namespaces` previously returned 200 with the same visible namespace choices; it now returns 503. No Namespace labels or readable memberships changed.

   This is neither the accepted commit-retry cliff nor the accepted unscoped `/paths` and `/backends` limitation.

   **Fix:** determine enumeration checks from a population independent of hidden-object occupancy. Cover hidden-bucket additions at the request limit.

6. **P3 correctness — The rule harness does not establish its claimed per-step sensitivity.**  
   [rule_test.go:1198](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/rule_test.go:1198), [export_rule_test.go:13](/Users/ddoyle/Development/claude/snellius-phase7/pkg/api/export_rule_test.go:13)

   The tests can fail: full-reader reach and bypass comparisons provide useful non-vacuity checks. However, bypass disables all projections together. A restored denied count can make the comparison fail while an independently broken context or state projection remains untested; that does not demonstrate sensitivity to “any step.”

   The rule surface table also has no route `state=` requests or cursor-following requests. Its fixtures do not exercise the CRD-hint branch, readable chains through hidden routes on readable Gateways, or the bounds above.

   **Fix:** add those observable cases and independently disable the relevant protections when checking mutation sensitivity.

7. **P3 correctness — The type-checked origin guard misses runtime assignments of `ClassOwn`.**  
   [ownrun_test.go:383](/Users/ddoyle/Development/claude/snellius-phase7/pkg/health/ownrun_test.go:383)

   `ownUseViolations` checks expressions only when `types.Info` supplies a constant value. Consequently, an assignment such as `f.Class = Class(n)` with runtime `n`, or `f.Class++` on a derived finding, escapes the guard. The bad fixtures cover constant expressions, including a variable initialized directly from `ClassOwn`, but not these cases.

   This leaves the claimed “only `fromOwn` can mark a finding own-object” protection incomplete. A future derived producer inside trusted `conditionsCheck` could bypass the boundary without this test rejecting it.

   **Fix:** enforce writes to the classification field, or make the origin marker inaccessible to ordinary producers; add negative fixtures for runtime conversion, increment and copied classification.
