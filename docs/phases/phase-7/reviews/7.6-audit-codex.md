## Review

Reviewed design §9, the 7.6 brief, and all four audit commits. Findings are from read-only source inspection.

- **P1 correctness — Default summaries can log sensitive query values.** `filtersOf` copies values by parameter name alone. `/installs` ignores query parameters and still succeeds, so a token or query text placed in `path` is retained. Requests logging also falls back to the decoded URL path on pre-routing failures, and `userAgent` copies arbitrary text with truncation. The existing secret test covers ordinary credential headers and `q`, leaving these paths untested. `pkg/api/audit.go:100`, `pkg/api/handlers.go:325`, `pkg/app/audit.go:62`, `pkg/audit/record.go:117`

- **P1 correctness — Disclosure mistakes arbitrary body data for object identity.** The recursive scan treats every map with `group`, `kind`, and `name` strings as an object. The raw resource endpoint preserves annotations, so coincidentally matching annotation keys can send arbitrary values, including credentials, to stdout as fabricated refs. The 1,000-ref cap applies after copying, decoding, walking, and sorting the full response. `pkg/api/audit.go:237`, `pkg/api/audit.go:255`, `pkg/api/audit.go:275`, `pkg/api/handlers.go:563`

- **P1 correctness — Failed writes count as written.** `slog.Logger.LogAttrs` discards the handler’s write error, then `write` increments `written` unconditionally. A failing sink can lose records while `written` rises and `dropped` stays flat. `pkg/audit/audit.go:220`

- **P2 correctness — Slow writes can merge windows.** The writer handles ticks and writes synchronously. Collection uses a single map per level with no time-based rollover, so requests arriving after a tick can join the previous window while the writer is stalled. `pkg/audit/audit.go:132`, `pkg/audit/audit.go:183`, `pkg/audit/window.go:33`

- **P2 correctness — Finding detail reads lack refs.** The route is classified as a read, but `findingDetail` never sets the audit subject even after resolving a visible finding with a resource. The default read record omits that resource. `pkg/api/audit.go:68`, `pkg/api/findings.go:299`, `pkg/app/audit.go:35`

- **P2 correctness — Secure CI skips the audit e2e.** The job selects only `TestSignIn`. Once selected, the six-minute allowance covers a five-minute production tick, but a 15-minute log search can pass on an earlier Alice session. Match both records to the current session and bound each `kubectl` call so a hung poll respects the deadline. `.github/workflows/e2e.yaml:102`, `test/e2e/signin_test.go:265`, `test/e2e/signin_test.go:281`, `test/e2e/api_test.go:250`

- **P3 correctness — Window tests have a startup race.** `HasWaiters` becomes true after the first ticker registers. The test can advance the fake clock before the denial ticker exists. Wait for both tickers. `pkg/audit/window_test.go:17`, `pkg/audit/audit.go:184`

**Checked and sound:** Core named reads authorize before object lookup, so an equally forbidden existing or absent name produces the same 404 and denial subject. I found no new existence-dependent audit timing on those paths. Add that same-name comparison to the denial test, which currently compares different permissions. Summaries count requests, filtered rows produce no denials, and disclosure scans the committed response only when enabled. The key cap, oldest-first eviction, locking, trusted-proxy source, and normal shutdown drain checked out.
